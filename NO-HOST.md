# Игра без ведущего

Добавлен режим «Все играют — без ведущего» на странице создания комнаты. Режим с отдельным ведущим остаётся доступен в списке.

## Как играть

1. Выберите квиз и создайте комнату в режиме «Все играют».
2. Покажите QR-код друзьям. Создатель тоже нажимает «Войти в комнату и играть» и вводит имя. Всего допускается 20 участников, включая организатора.
3. Первый успешно вошедший становится организатором. После входа QR-код остаётся доступен на экране игроков до старта.
4. Когда все собрались, организатор нажимает «Начать игру». После старта новые участники не подключаются; прежние могут восстановить доступ своим файлом.
5. Все, включая организатора, отвечают со своих устройств. Вопрос закрывается, когда ответили все либо истёк серверный таймер. Затем организатор переключает вопрос, начинает следующий тур или показывает итоговые места.
6. Если организатор перестал обновлять состояние в течение 30 секунд, управление при следующем обновлении получает самый ранний из активных участников. Вернувшийся организатор остаётся игроком. Баллы на порядок передачи не влияют.

## Правила и ограничения

- Существующие правила квиза определяют стоимость ответов, начисление баллов и момент раскрытия ответов: вопрос, тур или весь квиз.
- Доступны одиночный и множественный выбор, текст с заранее заданными допустимыми ответами, изображения, GIF, аудио и видео. Воспроизведение медиа сохраняет существующее поведение браузера.
- Квизы с ручной оценкой отклоняются сервером до создания комнаты: без ведущего некому оценивать произвольные ответы.
- Организатор получает только проекцию игрока. Секрет ведущего, редактор содержимого и будущие вопросы ему не выдаются.
- Досрочное раскрытие ответа, пропуск открытого вопроса и принудительное завершение через интерфейс организатора недоступны.
- Закрытие по таймеру выполняется сервером при запросе любого игрока. На видимом экране запросы идут каждые 2 секунды. Когда все закрыли страницы, фонового планировщика нет: состояние обновится при возвращении в игру.
- Телефон, надолго отправленный в фон, считается неактивным; управление может перейти следующему игроку. Участник сохраняет свои очки и ответы.

## Установка

1. Сохраните резервную копию базы. Требуется установленная версия из `game-reliability.sql`.
2. Примените `no-host.sql` через SQL Editor своего проекта Supabase. Миграция транзакционная, повторное применение поддерживается. Исходные комнаты получают режим `hosted`.
3. Выполните `no-host-tests.sql`. Все тестовые комнаты и квизы откатываются. Также выполните `game-reliability-tests.sql` для проверки режима с ведущим.
4. Опубликуйте обновлённые `room-test.html`, `player.html`, `player.js`, `player-controls.js`, `game-view.js`, `rich-game.js`, `game-summary.js` в GitHub Pages. Базу обновляют **до** файлов: новый режим вызывает новые серверные функции.
5. Проверьте игру с двух телефонов: вход по QR, запуск первым участником, ответы обоих, ожидание таймера, переход между турами, отключение организатора на 30 секунд, окончание игры и восстановление личного доступа.

SQL-файл в репозитории не применяется к Supabase автоматически. Локальная реализация сама по себе не меняет опубликованный сайт.

## Проверки разработки

`pnpm install`, затем `pnpm test` (или `npm install`, затем `npm test`). Тесты выполняются в PostgreSQL PGlite без сети и рабочих секретов. Для базовой схемы, которой нет в репозитории, используется явно описанная тестовая схема; существующие функции из игровых миграций загружаются из исходных файлов. Это не заменяет проверку установленной схемы, RLS и Realtime на настоящем Supabase.

Проверены повторное применение миграции, регрессия режима ведущего, вместимость, изоляция полномочий, отсутствие раннего ответа, закрытие по всем ответам и времени, повторные ответы и команды, смена организатора и его возвращение, стабильные итоговые отчёты, современные туры с дробными баллами, три режима начисления/раскрытия и запрет ручной проверки. В DOM проверены кнопки организатора, ссылка QR, границы туров, блокировка повторной команды и безопасный вывод имён.

## Возврат предыдущей версии

Верните прежние файлы интерфейса: новые столбцы имеют безопасные значения по умолчанию для обычных комнат. Для уже созданных комнат `everyone` сохраните новую страницу игрока до их окончания; старый клиент не предоставляет управления такими комнатами. Не запускайте старые SQL-миграции поверх новой версии: они заменят серверные обёртки.
