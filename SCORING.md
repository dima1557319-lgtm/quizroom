# Баллы и доступ ведущего

При создании комнаты выберите готовый квиз или «Создать свой квиз». На экране ведущего до начала игры у каждого вопроса задаются баллы (0–10000, до двух знаков после запятой) и время. Например, три вопроса одного квиза могут приносить 0,5, 1 и 1,5 балла. По умолчанию — 1 балл. За неверный ответ — 0. Скорость не меняет баллы.

Выберите начисление после каждого вопроса либо только в конце квиза. В первом режиме баллы появляются при раскрытии ответа, во втором таблица остаётся без баллов до итогов. Повторная отправка ответа или нажатие кнопки не удваивает результат. После старта настройки закрыты. В уже начатых до обновления играх сохраняется прежняя стоимость 1000, чтобы не смешивать правила.

Готовые квизы берут вопросы и правильные ответы из серверного шаблона: ведущий настраивает время и баллы, но не редактирует содержание. Редактор доступен только при явном создании своего квиза. Первый вошедший игрок не получает права ведущего. Сервер проверяет отдельный секрет создателя комнаты; секрет игрока не подходит. Вкладка после входа игроком удаляет сохранённый доступ ведущего и скрывает ссылку возврата. Для одновременной проверки используйте разные вкладки: ведущего не переводите в роль игрока.

## Публикация

1. В Supabase SQL Editor выполните `scoring-access.sql` после `host-lobby.sql` и `game.sql` (если они уже применены, повторять их не надо).
2. Для проверки выполните `scoring-access-tests.sql`. Ожидается PASS. Тесты создают временные комнаты внутри транзакции и откатывают их.
3. Опубликуйте обновлённые HTML/JS из этого изменения в основной ветке GitHub Pages. Сначала база, затем страницы.
4. Откройте главную заново. Создайте свой квиз из трёх вопросов, укажите 0,5 / 1 / 1,5. В другой вкладке войдите по QR или коду. Дайте правильные ответы: итог должен быть 3.
5. Повторите с режимом «Только в конце квиза»: до итогов — 0, после итогов — 3.
6. Создайте готовый квиз: редактора правильных ответов быть не должно. Во вкладке игрока откройте `host.html`: ожидается отказ в доступе. Создание комнаты, QR, вход и обновление списка должны работать как раньше.

Серверные проверки находятся в `scoring-access-tests.sql`. Исторический `game-tests.sql` относится к старому свободному редактору и не используется после этой миграции: готовые квизы теперь намеренно запрещают подмену содержимого.
