# Многораундовые игры

В закрытом редакторе `admin.html` сохранена кнопка «Новый простой квиз». Она создаёт прежний формат и поддерживает существующий сценарий игры.

«Игра на 7 туров» создаёт заготовку из 39 пустых вопросов; «Многораундовая с нуля» — один тур. Это структура для собственных материалов, без заимствованных вопросов. Перед публикацией заполните все тексты, варианты и правильные ответы.

Для каждого тура задаются:
- общий редактируемый бланк или окончательный ответ на каждый вопрос;
- сложность, длительность вопросов и стоимость в баллах;
- повтор, время сдачи, автоматическое или ручное продолжение;
- раскрытие ответов и начислений после вопроса, тура либо игры;
- ставки 0/1/2: верно — стоимость плюс ставка, ошибка — минус ставка, пусто — ноль;
- перерыв с таймером или до команды организатора;
- начало обсуждения вместе с вопросом либо после аудио/видеофрагмента на общем экране.

Многораундовая игра работает в режиме «Все играют» до 20 участников. Первый вошедший управляет этапами и тоже отвечает. При потере связи действуют существующие правила передачи управления. Вход — по QR/ссылке комнаты. Ответы проверяет сервер; открытый ответ должен совпасть с одним из вариантов после нормализации регистра, пробелов и ё/е. Для множественного выбора доступны прежние правила точного/частичного зачёта; ставки требуют точного зачёта. Ручная проверка исключена из этого режима, чтобы игра обходилась без ведущего.

Ответы общего бланка нужно сохранять, затем подтвердить сдачу. Локальные несохранённые правки помечены и не подменяют серверный ответ. После сдачи изменения закрываются. По истечении срока сервер фиксирует сохранённое; пропуски дают ноль. Правильные ответы не передаются до выбранного этапа разбора.

Кнопка общего экрана скрывает личные ответы на устройстве организатора. Для медиа после фрагмента организатор запускает обсуждение; сервер не позволяет запустить его раньше длительности фрагмента. Нужен доступный прямой URL медиа, а не страница видеохостинга.

Итоги содержат сумму и баллы по турам. На выбор автора: разделённое место либо сравнение результатов с последнего тура к первому при одинаковой сумме. Отчёт сохраняется на сервере и экспортируется в CSV. Предпросмотр проигрывает сценарий локально без комнаты, игроков и начислений в базе.

## Развёртывание

1. После существующих `admin-studio.sql`, `game-reliability.sql`, `no-host.sql` применить `classic-game.sql` одной транзакцией. Скрипт допускает повторное применение, сохраняет старый движок под закрытыми функциями. Сделать резервную копию функций и данных перед обновлением.
2. Проверить `classic-tests.sql` — тестовые изменения полностью откатываются. В рабочей базе выполнять отдельным запросом, не вместе с миграцией.
3. Опубликовать изменённые HTML/JS/CSS и новые модули classic. Дождаться GitHub Pages.
4. Проверить закрытый редактор, оба формата, предпросмотр и игру с двумя участниками.

Локальные проверки: `npm install`, затем `npm test`. Тесты используют PostgreSQL через PGlite и DOM через LinkeDOM. Параметр `QUIZROOM_TEST_MODULES` позволяет указать уже установленный каталог зависимостей.
