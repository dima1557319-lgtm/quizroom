## Изменения

room-test.html отличается только ссылкой на host.html, открываемой в той же вкладке. QR и существующие вызовы создания/входа сохранены. join.html и supabase-client.js — неизменённые копии для справки; заменять их при публикации не нужно.

host.html / host.js отображают список через textContent, счётчик 0–20, пустое состояние, обновление при возврате к вкладке и резервный опрос каждые 5 секунд. После потери связи список отмечается как потенциально устаревший. В новой независимой вкладке без секрета доступ закрыт. Секрет не включается в URL, QR или сообщения realtime. Закрытие вкладки теряет сохранённый доступ; страницу создания можно открыть заново, но она не восстанавливает QR старой комнаты.

host-lobby.sql добавляет колонку lobby_topic, RPC get_quiz_host_lobby и триггер уведомлений. RPC проверяет host_token и возвращает только id/имя игроков, код и случайный topic; player_token и host_token не возвращаются. Общий SELECT на таблицы не открывается. Realtime Broadcast передаёт пустой сигнал; список всегда перечитывается через защищённый RPC.

Канал Broadcast публичный, с непредсказуемым UUID в имени. Это осознанный выбор без нового Supabase Auth: даже знающий topic не получает имён или секретов через сообщения, но может видеть сигналы активности или посылать ложные сигналы перечитывания. Секрет ведущего остаётся обязательным для данных. Публичные Broadcast-каналы должны быть разрешены в Realtime; при запрете останется только резервный опрос. Не отключайте имеющееся ограничение private-only ради этой версии — тогда нужна отдельная версия с Supabase Auth и private channels.

## Публикация по шагам

1. Сохраните копию текущих файлов GitHub и экспорт схемы Supabase. Для повторного чтения схемы есть inspect-schema.sql: он только читает метаданные.
2. В Supabase → SQL Editor → New query вставьте содержимое host-lobby.sql и нажмите Run. Скрипт выполняется транзакцией; при ошибке не переходите к публикации. Он сохраняет create_quiz_room, join_quiz_room и ограничения вместимости.
3. В GitHub откройте dima1557319-lgtm/quizroom. Создайте ветку host-lobby. Через Add file → Upload files загрузите host.html, host.js, room-test.html, host-lobby.sql. Не загружайте заново join.html и supabase-client.js.
4. Создайте pull request в main, проверьте, что room-test.html содержит только добавленную ссылку, а существующие файлы входа и клиента не изменились. Слейте PR после проверки.
5. В Settings → Pages проверьте текущий источник публикации. Если используется Deploy from a branch, выберите main и /(root), сохраните. Если Pages уже настроен через Actions, сохраните существующий способ и дождитесь успешного запуска в Actions.
6. Откройте https://dima1557319-lgtm.github.io/quizroom/room-test.html и обновите страницу без кеша. Создайте новую комнату, сохраните QR на экране, откройте ссылку «Открыть экран ведущего» в той же вкладке.

## Проверка после публикации

Локальные проверки интерфейса пройдены: закрытый доступ без секрета, пустая комната, безопасный текст имени, заполненная комната (20), отказ доступа от сервера. Синтаксис host.js проверен. Эти проверки используют имитацию ответов сервера и не заменяют проверки Supabase и realtime ниже.

1. Два телефона сканируют QR или открывают join.html?code=XXXXXX. Проверьте имена в списке ведущего и счётчик 2 / 20 без ручного обновления.
2. Перезагрузите host.html в той же вкладке: список должен восстановиться. Откройте host.html в отдельном приватном окне: список недоступен.
3. В SQL Editor вызовите get_quiz_host_lobby с кодом тестовой комнаты и неправильным UUID: должен быть отказ 42501. Не вставляйте настоящий секрет в общий чат или скриншот.
4. В тестовой комнате подключите 20 игроков; 21-й получает ошибку, остаётся 20. Затем проверьте два одновременных входа при 19 игроках: один успешный, второй отклонён.
5. В качестве имени введите <img src=x onerror=alert(1)>: оно должно отображаться обычным текстом, без выполнения.
6. Временно отключите сеть у ведущего, затем восстановите: должна появиться отметка об ошибке, после восстановления — актуальный список. Если realtime недоступен, обновления должны приходить через опрос.
7. Убедитесь, что QR и ссылка игрока содержат только code; в payload Broadcast нет имён и токенов. Проверяйте realtime по индикатору «Обновление в реальном времени подключено»; обновление за 5 секунд само по себе доказывает только работу опроса.
